# 3.7 Risk Management

Risks were recorded whenever an experiment behaved unexpectedly or a phase was reviewed, and each was rated for likelihood and for impact on the validity of the results, the schedule or user safety. Wherever possible the mitigation was structural rather than procedural, meaning an automatic check, a fixed seed or a pinned library version, so the same failure could not recur unnoticed. Twelve risks were identified; eight occurred, two were prevented in advance and two remain open. The full register is Table A.2, and three entries changed how the project works.

- **Silent technical failure (R3):** the design reads the detector's attention weights to find the words that drove its prediction, but with the library's default attention implementation {cite:wolf2020transformers} asking for those weights returns nothing without raising an error, so cue extraction quietly fell back to plain text splitting while appearing to work. Left unnoticed, the thesis would have described a mechanism that was not running. The implementation was changed and an automatic check now halts execution if the weights are missing.
- **Validity of results (R4, R5):** the original detector was trained on situation descriptions but used on the user's own messages, and its accuracy fell from 56.9% to 48.2% once measured on the real input, so it was retrained on the correct text. Separately, a RoBERTa-large run diverged to 5.0% accuracy through a missing learning-rate warmup; rather than report that number, the cause was found and the run repeated, reaching 53.0%.
- **Dependence on external services (R7, R8):** the AI judges were free APIs outside the team's control, and several candidates were retired or restricted mid-project. The panel was fixed on the two that stayed available throughout, so every system is scored by identical judges, and rate-limited work was split between two accounts with every emotion represented in each half.

Two risks remain open. A late design change would invalidate the collected judge scores and the human-evaluation items, so those outputs are frozen and the repetition-penalty improvement is deferred. And apart from interface disclaimers the system still has no safeguard for disclosures of suicidal thinking, which must be resolved before any deployment (Section 3.4).
